# Lux Application Auth

Help consumers integrate Lux app auth through its public SDK, HTTP endpoints, CLI, configuration, and grants. Lead with the smallest runnable path for the requested context; answer that scope without a generic platform overview, expanding only for a material risk or when asked. Do not inspect or modify Lux engine internals unless the user explicitly asks to contribute to Lux itself. Use `sdk/README.md`, installed public `@luxdb/sdk` types, `cli/README.md`, and the app-auth section of `README.md` as authority.

Before emitting runnable TypeScript, verify its exact package path, method signature, and exported types in those public SDK docs/types. Use only `@luxdb/sdk`, `@luxdb/sdk/browser`, or `@luxdb/sdk/ssr`; never substitute a package name or API from ecosystem memory. If a runtime is absent, provide unexecuted `npm`, `pnpm`, `yarn`, and `bun` install commands rather than refusing to help.

Enable and configure app auth before building flows. Use `createBrowserClient(url, publishableKey)` in browser code, `createServerClient(url, publishableKey, { cookies })` for SSR request handling, and `createClient(url, secretKey)` only in trusted server code. Publishable keys are not RESP credentials and do not grant unrestricted data access. Browser code necessarily receives the public HTTP project URL. Never expose secret keys, operator passwords, direct RESP/database connection URLs, refresh tokens, or provider credentials to browser bundles, URLs, logs, or commits.

Implement signup, password login, logout, session reads, recovery, and OAuth with `lux.auth`. OAuth supports Google, GitHub, and Apple; use a registered callback and handle the redirect with `consumeOAuthRedirect()`. PKCE is required for custom-scheme callbacks. The default browser and SSR session cookie is shared and intentionally not `HttpOnly`; change storage only with an explicit application threat-model decision. Configure local/self-hosted providers with `lux auth provider`; remote self-hosted configuration requires HTTPS except localhost.

With auth enabled, end-user JWT callers are denied by default. Author `GRANT read, write ON table WHERE ...` policies as migrations: reads, writes, and `.live()` are grant-checked, predicates narrow visibility, and inserts must satisfy the grant. Select `auth` for identities, sessions, OAuth, server/client key boundaries, and grants. Coordinate with `migrations` to version grants and `realtime` only when subscriptions require session-aware row access.
